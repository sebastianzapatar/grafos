¿Qué es un Grafo?

Estructura de datos fundamental en ciencias de la computación

Definición Formal

Un grafo G = (V, E) es un par ordenado donde:

  • V = conjunto finito de vértices (nodos)
  • E ⊆ V × V = conjunto de aristas (conexiones)

Terminología Clave

  • Grado: número de aristas que inciden en un nodo
  • Camino: secuencia de vértices conectados por aristas
  • Ciclo: camino que inicia y termina en el mismo nodo
  • Grafo conexo: existe camino entre todo par de nodos
  • DAG: Directed Acyclic Graph (clave en compiladores)

Grafo Dirigido

Las aristas tienen dirección: (u, v) ≠ (v, u)

Ejemplo: flujo de control en un compilador

Grafo No Dirigido

Las aristas no tienen dirección: {u, v} = {v, u}

Ejemplo: red social de amistades

Grafo Ponderado

Cada arista tiene un peso/costo asociado: w(u,v)

Ejemplo: mapa de rutas con distancias

BFS — Búsqueda en Anchura

Explora nivel por nivel usando una Cola (FIFO) · Complejidad: O(V + E)

Listo
BFS(grafo, inicio): cola ← [inicio] visitado[inicio] ← true mientras cola no vacía: nodo ← cola.dequeue() para cada vecino de nodo: si no visitado[vecino]: visitado[vecino] ← true cola.enqueue(vecino)
Java public void bfs(int start) { // Array de visitados: evita ciclos boolean[] visited = new boolean[V]; // Distancia por aristas desde start int[] distance = new int[V]; // Cola FIFO: procesa nivel por nivel Queue<Integer> queue = new LinkedList<>(); // Inicializar nodo origen visited[start] = true; distance[start] = 0; queue.add(start); while (!queue.isEmpty()) { // Extraer frente de la cola int node = queue.poll(); // Explorar vecinos for (int nb : adj.get(node)) { if (!visited[nb]) { visited[nb] = true; distance[nb] = distance[node] + 1; queue.add(nb); } } } }

Dijkstra — Camino Más Corto

Algoritmo greedy con PriorityQueue · O((V+E) log V) · Solo pesos ≥ 0

Listo
Dijkstra(grafo, inicio): dist[*] ← ∞; dist[inicio] ← 0 pq ← MinHeap con (inicio, 0) mientras pq no vacía: (u, d) ← pq.extractMin() si d > dist[u]: continuar para cada arista (u→v, peso w): si dist[u] + w < dist[v]: // Relajar dist[v] ← dist[u] + w pq.insert(v, dist[v])
Java public void dijkstra(int start) { int[] dist = new int[V]; Arrays.fill(dist, Integer.MAX_VALUE); dist[start] = 0; // Min-heap: ordena por distancia PriorityQueue<int[]> pq = new PriorityQueue<>( Comparator.comparingInt(a -> a[1]) ); pq.add(new int[]{start, 0}); while (!pq.isEmpty()) { int[] curr = pq.poll(); int u = curr[0], d = curr[1]; // Obsoleto si ya hay mejor camino if (d > dist[u]) continue; // RELAJACIÓN de aristas for (Edge e : adj.get(u)) { if (dist[u] + e.weight < dist[e.target]) { dist[e.target] = dist[u] + e.weight; pq.add(new int[]{ e.target, dist[e.target] }); } } } }

Bellman-Ford

Soporta pesos negativos · Detecta ciclos negativos · O(V × E)

Listo
BellmanFord(grafo, inicio): dist[*] ← ∞; dist[inicio] ← 0 repetir V-1 veces: para cada arista (u→v, peso w): si dist[u] + w < dist[v]: dist[v] ← dist[u] + w // Detectar ciclos negativos: para cada arista (u→v, peso w): si dist[u] + w < dist[v]: error "Ciclo negativo"
Java public void bellmanFord(int start) { int[] dist = new int[V]; Arrays.fill(dist, Integer.MAX_VALUE); dist[start] = 0; // V-1 iteraciones: el camino más // largo sin ciclos tiene V-1 aristas for (int i = 1; i < V; i++) { // Relajar TODAS las aristas for (Edge e : edges) { if (dist[e.source] != MAX && dist[e.source] + e.weight < dist[e.target]) { // ¡Camino más corto! dist[e.target] = dist[e.source] + e.weight; } } } // Iteración extra = ciclo negativo for (Edge e : edges) { if (dist[e.source] + e.weight < dist[e.target]) { System.out.println( "¡Ciclo negativo!"); } } }

Floyd-Warshall — Todos los Pares

Programación dinámica · Distancia mínima entre TODOS los pares · O(V³)

Listo
FloydWarshall(grafo): dist[][] ← matriz de pesos del grafo // k = vértice intermedio para k ← 0 hasta V-1: para i ← 0 hasta V-1: para j ← 0 hasta V-1: si dist[i][k] + dist[k][j] < dist[i][j]: dist[i][j] ← dist[i][k] + dist[k][j] // Si dist[i][i] < 0 → ciclo negativo

Idea Central

Para cada par (i, j), ¿conviene pasar por un nodo intermedio k?

dist[i][j] = min( dist[i][j], // camino directo dist[i][k] + dist[k][j] // vía k )
Java // Triple bucle: k DEBE ser externo for (int k = 0; k < V; k++) { for (int i = 0; i < V; i++) { for (int j = 0; j < V; j++) { if (dist[i][k] != INF && dist[k][j] != INF && dist[i][k] + dist[k][j] < dist[i][j]) { dist[i][j] = dist[i][k] + dist[k][j]; next[i][j] = next[i][k]; } } } }

¿Qué es un Ciclo?

Camino que inicia y termina en el mismo vértice · Detección con DFS · O(V + E)

Listo

DFS con 3 colores (grafos dirigidos)

BLANCO: sin visitar · GRIS: en la pila de recursión · NEGRO: terminado

Si una arista apunta a un nodo GRIS → volvimos a un nodo de nuestro propio camino → ¡hay ciclo! (back edge). Un grafo dirigido sin ciclos es un DAG.

En grafos no dirigidos: hay ciclo si un vecino ya visitado NO es el padre del nodo actual.

Java — DeteccionCiclos.java // BLANCO=0, GRIS=1, NEGRO=2 private boolean dfsCiclo(int u, int[] color) { color[u] = GRIS; // entra a la recursión for (int v : adj.get(u)) { if (color[v] == GRIS) { // ¡Back edge! v está en // nuestro camino actual return true; // CICLO } if (color[v] == BLANCO) { parent[v] = u; if (dfsCiclo(v, color)) return true; } // NEGRO: ya explorado, ignorar } color[u] = NEGRO; // sale de la recursión return false; }

¿Por qué no basta "visitado sí/no"?

En el DAG 0→1→3 y 0→2→3, el nodo 3 se alcanza por dos caminos sin haber ciclo. El GRIS distingue "está en MI camino" de "ya explorado por otro lado".

Ciclos Negativos

Ciclo cuya suma de pesos es < 0 (ej: 3 + 2 + (−7) = −2) · El camino más corto deja de existir

Listo

¿Por qué son un problema?

Cada vuelta al ciclo reduce el costo total: la "distancia mínima" tiende a −∞ y el camino más corto no está definido. Por eso Dijkstra no los soporta.

Detección: Bellman-Ford con una iteración extra (si algo aún se relaja → ciclo negativo), o Floyd-Warshall si dist[i][i] < 0.

Java — CicloNegativo.java (reconstrucción) int[] dist = new int[V]; // en 0: busca en TODO el grafo int[] parent = new int[V]; int x = -1; // último nodo relajado // V iteraciones (una MÁS que Bellman-Ford) for (int i = 0; i < V; i++) { x = -1; for (Edge e : edges) { if (dist[e.source] + e.weight < dist[e.target]) { dist[e.target] = dist[e.source] + e.weight; parent[e.target] = e.source; x = e.target; // hubo relajación } } } // ¿La iteración V aún relajó? → ciclo negativo if (x == -1) return sinCiclo; // Retroceder V veces para caer DENTRO del ciclo for (int i = 0; i < V; i++) x = parent[x]; // Seguir parent[] hasta cerrar el ciclo for (int v = x; ; v = parent[v]) { ciclo.add(v); if (v == x && ciclo.size() > 1) break; }

Kahn — Orden Topológico

Resuelve dependencias en un DAG usando grados de entrada (In-Degree) y una Cola · O(V + E)

Listo
Kahn(DAG): inDegree[*] ← 0 para cada arista (u→v): inDegree[v]++ cola ← {nodos con inDegree == 0} mientras cola no vacía: u ← cola.dequeue() procesar(u) para cada vecino v de u: inDegree[v]-- si inDegree[v] == 0: cola.enqueue(v)
Java public void topologicalSort() { int[] inDegree = new int[V]; for (int i = 0; i < V; i++) { for (int neighbor : adj.get(i)) { inDegree[neighbor]++; } } Queue<Integer> queue = new LinkedList<>(); for (int i = 0; i < V; i++) { if (inDegree[i] == 0) queue.add(i); } List<Integer> topOrder = new ArrayList<>(); while (!queue.isEmpty()) { int node = queue.poll(); topOrder.add(node); for (int neighbor : adj.get(node)) { inDegree[neighbor]--; if (inDegree[neighbor] == 0) { queue.add(neighbor); } } } }

Union-Find — Union y Union by Rank

DSU (Disjoint Set Union): la estructura que hace eficiente a Kruskal · find() + union()

¿Qué es Union-Find?

Mantiene conjuntos disjuntos. Dos operaciones:

  • find(x): ¿a qué conjunto pertenece x? (devuelve la raíz)
  • union(x,y): fusionar los conjuntos de x e y

En Kruskal: si find(u) == find(v), agregar la arista u—v formaría un ciclo.

Path Compression (find)

Al buscar la raíz, colgamos cada nodo directamente de ella:

Antes: 0←1←2←3 (cadena) find(3): recorre 3→2→1→0 Después: 0←1, 0←2, 0←3 (plano)

Union Naive vs Union by Rank

Union Naive Union by Rank
Estrategia Cuelga rx de ry (arbitrario) Cuelga el más bajo del más alto
Peor caso O(n) sin PC O(log n) sin PC
Con PC O(log n) amort. O(α(n)) ≈ O(1)

PC = Path Compression · α = inversa de Ackermann

Java — Union Naive // Union NAIVE: cuelga rx de ry sin // considerar cuál árbol es más alto boolean union(int x, int y) { int rx = find(x); int ry = find(y); if (rx == ry) return false; // Siempre cuelga rx de ry // (puede crear cadenas largas) parent[rx] = ry; return true; }
Java — Union by Rank // UNION BY RANK: el árbol más bajo // se cuelga del más alto → O(α(n)) boolean union(int x, int y) { int rx = find(x); int ry = find(y); if (rx == ry) return false; if (rank[rx] < rank[ry]) { parent[rx] = ry; // rx más bajo } else if (rank[rx] > rank[ry]) { parent[ry] = rx; // ry más bajo } else { parent[ry] = rx; // misma h. rank[rx]++; // crece en 1 } return true; }
Java — find (Path Compression) // find con PATH COMPRESSION // Cuelga cada nodo directo de la raíz int find(int x) { if (parent[x] != x) parent[x] = find(parent[x]); return parent[x]; }

Kruskal — MST

Greedy por Aristas. Usa Union-Find (Disjoint Set) para evitar ciclos · O(E log E)

Listo
Kruskal(grafo): ordenar aristas por peso ascendente mst ← [] uf ← UnionFind(V) para cada arista (u-v, peso) en orden: si uf.find(u) ≠ uf.find(v): uf.union(u, v) mst.add(arista) si mst.tamaño() == V-1: romper retornar mst
Java public void kruskal() { // 1. Ordenar aristas por peso ascendente Collections.sort(edges); UnionFind uf = new UnionFind(V); List<Edge> mst = new ArrayList<>(); int costoTotal = 0; // 2. Procesar cada arista for (Edge e : edges) { // union() devuelve true si u y v // estaban en conjuntos diferentes if (uf.union(e.u, e.v)) { mst.add(e); costoTotal += e.weight; // 3. Parar al tener V-1 aristas if (mst.size() == V - 1) break; } } }

Prim — MST

Greedy por Nodos. Hace crecer un único árbol usando PriorityQueue · O((V+E) log V)

Listo
Prim(grafo, inicio): minCost[*] ← ∞; minCost[inicio] ← 0 pq ← MinHeap con (inicio, 0) mientras pq no vacía: u ← pq.extractMin() si enArbol[u]: continuar enArbol[u] ← true para cada vecino v de u con peso w: si no enArbol[v] y w < minCost[v]: minCost[v] ← w padre[v] ← u pq.insert(v, w)
Java public void prim(int start) { boolean[] enArbol = new boolean[V]; int[] minCost = new int[V]; int[] parent = new int[V]; Arrays.fill(minCost, Integer.MAX_VALUE); Arrays.fill(parent, -1); minCost[start] = 0; PriorityQueue<int[]> pq = new PriorityQueue<>( Comparator.comparingInt(a -> a[1])); pq.add(new int[]{start, 0}); while (!pq.isEmpty()) { int u = pq.poll()[0]; if (enArbol[u]) continue; enArbol[u] = true; for (Edge e : adj.get(u)) { if (!enArbol[e.target] && e.weight < minCost[e.target]) { minCost[e.target] = e.weight; parent[e.target] = u; pq.add(new int[]{e.target, e.weight}); } } } }

Ejercicio 1 — BFS

Recorrido BFS: Determinar el orden de visita

Dado el siguiente grafo dirigido, determina el orden de visita BFS comenzando desde el nodo 0:

Nodos: {0, 1, 2, 3, 4, 5} Aristas: 0→1, 0→2, 1→3, 1→4, 2→4, 2→5, 3→5, 4→5 Representación visual: 0 / \ 1 2 / \ / \ 3 4 5 \ | / → 5 ←

Pregunta: ¿Cuál es el orden de visita BFS? ¿Cuál es la distancia (en aristas) del nodo 0 al nodo 5?

Solución

Orden BFS: 0, 1, 2, 3, 4, 5

Explicación paso a paso:

  • Inicio: Cola = [0], Visitados = {0}
  • Sacar 0 → vecinos 1, 2 → Cola = [1, 2], Visitados = {0, 1, 2}
  • Sacar 1 → vecinos 3, 4 → Cola = [2, 3, 4], Visitados = {0, 1, 2, 3, 4}
  • Sacar 2 → vecinos 4(visitado), 5 → Cola = [3, 4, 5], Visitados = {0, 1, 2, 3, 4, 5}
  • Sacar 3 → vecino 5(visitado) → Cola = [4, 5]
  • Sacar 4 → vecino 5(visitado) → Cola = [5]
  • Sacar 5 → sin vecinos → Cola = []

Distancia de 0 a 5: 2 aristas (camino 0→2→5)

Componentes Conexas con DFS

Dado el siguiente grafo no dirigido, encuentra todas las componentes conexas usando DFS:

Nodos: {0, 1, 2, 3, 4, 5, 6, 7} Aristas: 0-1, 0-2, 1-2, 3-4, 5-6, 5-7, 6-7 Visualmente: Componente A Componente B Componente C 0 --- 1 3 --- 4 5 --- 6 | / | / 2 7

Pregunta: ¿Cuántas componentes hay? ¿Cuáles son los nodos de cada una?

Solución

3 componentes conexas:

  • Componente 1: {0, 1, 2} — DFS desde 0: visita 0→1→2
  • Componente 2: {3, 4} — DFS desde 3: visita 3→4
  • Componente 3: {5, 6, 7} — DFS desde 5: visita 5→6→7

Algoritmo: Para encontrar componentes, iterar sobre todos los nodos. Si un nodo no ha sido visitado, lanzar DFS desde él → todos los nodos visitados en ese DFS forman una componente.

Java public int contarComponentes() { boolean[] visitados = new boolean[V]; int componentes = 0; for (int i = 0; i < V; i++) { if (!visitados[i]) { componentes++; dfs(i, visitados); // Visita todo el componente } } return componentes; } private void dfs(int u, boolean[] visitados) { visitados[u] = true; for (int v : adj.get(u)) { if (!visitados[v]) dfs(v, visitados); } }

Ejercicio 3 — Dijkstra

Camino más corto con Dijkstra

Aplica Dijkstra desde el nodo A en el siguiente grafo ponderado:

A --4-- B --2-- D | | / | 2 1 3 6 | | / | C --5-- E --1-- F Aristas: A→B(4), A→C(2), B→D(2), B→E(1), C→E(5), D→F(6), E→D(3), E→F(1)

Pregunta: ¿Cuál es la distancia mínima de A a cada nodo? ¿Cuál es el camino más corto de A a F?

Solución

Distancias mínimas desde A:

  • A → A: 0
  • A → B: 4 (A→B)
  • A → C: 2 (A→C)
  • A → D: 6 (A→B→D, 4+2=6)
  • A → E: 5 (A→B→E, 4+1=5)
  • A → F: 6 (A→B→E→F, 4+1+1=6)

Camino más corto A→F: A → B → E → F (costo: 6)

Nota: A→C→E→F (2+5+1=8) es más largo aunque A→C es la arista más barata desde A

Java public void dijkstra(int start) { int[] dist = new int[V]; Arrays.fill(dist, Integer.MAX_VALUE); dist[start] = 0; PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[1] - b[1]); pq.add(new int[]{start, 0}); while (!pq.isEmpty()) { int[] actual = pq.poll(); int u = actual[0], d = actual[1]; if (d > dist[u]) continue; // Ya encontramos un camino mejor antes for (Edge e : adj.get(u)) { if (dist[u] + e.weight < dist[e.target]) { dist[e.target] = dist[u] + e.weight; pq.add(new int[]{e.target, dist[e.target]}); } } } }

Ejercicio 4 — Bellman-Ford

Detectar Ciclo Negativo

Aplica Bellman-Ford desde el nodo 0. ¿Hay un ciclo de peso negativo?

Nodos: {0, 1, 2, 3} Aristas: 0→1 (1), 1→2 (3), 2→3 (2), 3→1 (-7) Visualmente: 0 --1-→ 1 --3-→ 2 ↑ | | -7 2 | | 3 ←-----+ Ciclo: 1 → 2 → 3 → 1 (peso: 3 + 2 + (-7) = -2)

Solución

¡SÍ hay un ciclo negativo! El ciclo 1→2→3→1 tiene peso total = 3 + 2 + (-7) = -2

Detección: Después de V-1 = 3 iteraciones de Bellman-Ford, hacemos una iteración extra. Si alguna arista aún puede relajarse, hay ciclo negativo.

  • Iteración 1: dist = [0, 1, ∞, ∞] → [0, 1, 4, ∞]
  • Iteración 2: dist = [0, 1, 4, 6] (relajamos 2→3)
  • Iteración 3: dist = [0, -1, 4, 6] (3→1: 6-7=-1 < 1 ✓)
  • Iteración extra: 1→2 se relaja (-1+3=2 < 4) → ¡CICLO NEGATIVO!
Java public boolean tieneCicloNegativo(int start) { int[] dist = new int[V]; Arrays.fill(dist, Integer.MAX_VALUE); dist[start] = 0; // Relajar todas las aristas V-1 veces for (int i = 1; i < V; i++) { for (Edge e : edges) { if (dist[e.source] != Integer.MAX_VALUE && dist[e.source] + e.weight < dist[e.target]) { dist[e.target] = dist[e.source] + e.weight; } } } // Iteración extra para detectar ciclos for (Edge e : edges) { if (dist[e.source] != Integer.MAX_VALUE && dist[e.source] + e.weight < dist[e.target]) { return true; // ¡Ciclo negativo encontrado! } } return false; }

Calcular la Matriz de Distancias Mínimas

Aplica Floyd-Warshall al siguiente grafo. Completa la matriz de distancias mínimas:

Nodos: {0, 1, 2, 3} Aristas: 0→1 (5), 0→3 (10), 1→2 (3), 2→3 (1) Matriz inicial: 0 1 2 3 0 [ 0, 5, ∞, 10 ] 1 [ ∞, 0, 3, ∞ ] 2 [ ∞, ∞, 0, 1 ] 3 [ ∞, ∞, ∞, 0 ]

Pregunta: ¿Cuál es la distancia mínima de 0 a 3? ¿Por qué camino?

Solución

Matriz final:

0 1 2 3 0 [ 0, 5, 8, 9 ] 1 [ ∞, 0, 3, 4 ] 2 [ ∞, ∞, 0, 1 ] 3 [ ∞, ∞, ∞, 0 ]

Ejercicio 30 — Counting Rooms

CSES · Graph Algorithms cses.fi/problemset/task/1192 DFS

¿Cuántas habitaciones tiene el edificio?

Se da el mapa de un edificio como una grilla de n × m, donde cada casilla es piso (.) o pared (#). Se puede caminar entre casillas de piso moviéndose arriba, abajo, izquierda o derecha. Contar el número de habitaciones.

Entrada: n y m (1 ≤ n, m ≤ 1000), luego n líneas de m caracteres Salida: un entero — el número de habitaciones Ejemplo de entrada Salida 5 8 3 ######## #..#...# ####.#.# #..#...# ########

Pregunta: ¿Dónde está el grafo? ¿Y por qué una solución recursiva en Java revienta con n = m = 1000?

Solución

El grafo es implícito: cada casilla de piso es un nodo y hay una arista entre casillas de piso adyacentes. Nunca se construye la lista de adyacencia: los vecinos se calculan con (i±1, j) y (i, j±1).

Con esa lectura el problema es literalmente el Ejercicio 2: contar componentes conexas. Se recorren todas las casillas y, al encontrar piso sin visitar, se lanza un flood fill que marca toda su componente y se suma 1 al contador.

La trampa de Java: con 1000×1000 = 106 casillas, una habitación en zigzag da una recursión de profundidad 106 → StackOverflowError. Solución: DFS con pila explícita (o BFS con cola: da igual el orden, solo hay que tocar toda la componente).

Complejidad: O(n·m) en tiempo y memoria — cada casilla se visita una sola vez. Respuesta del ejemplo: 3.

Java public static int contarHabitaciones(char[][] g) { int n = g.length, m = g[0].length; boolean[][] visitado = new boolean[n][m]; int[] di = {1, -1, 0, 0}, dj = {0, 0, 1, -1}; int habitaciones = 0; Deque<int[]> pila = new ArrayDeque<>(); // pila EXPLÍCITA for (int i = 0; i < n; i++) { for (int j = 0; j < m; j++) { if (g[i][j] == '#' || visitado[i][j]) continue; habitaciones++; // componente nueva visitado[i][j] = true; pila.push(new int[]{i, j}); while (!pila.isEmpty()) { // flood fill int[] actual = pila.pop(); for (int d = 0; d < 4; d++) { int ni = actual[0] + di[d], nj = actual[1] + dj[d]; if (ni < 0 || ni >= n || nj < 0 || nj >= m) continue; if (visitado[ni][nj] || g[ni][nj] == '#') continue; visitado[ni][nj] = true; // marcar AL APILAR pila.push(new int[]{ni, nj}); } } } } return habitaciones; }

Ejercicio 31 — Labyrinth

CSES · Graph Algorithms cses.fi/problemset/task/1193 BFS

Salir del laberinto por el camino más corto

Grilla de n × m con paredes (#), piso (.), inicio (A) y salida (B). Hay que decir si existe camino de A a B y, si existe, imprimir su longitud mínima y la secuencia de movimientos (L, R, U, D).

Entrada: n y m (1 ≤ n, m ≤ 1000) y la grilla Salida: "NO", o bien "YES", la longitud y los movimientos Ejemplo de entrada Salida 5 8 YES ######## 9 #.A#...# LDDRRRRRU #.##.#B# #......# ########

Pregunta: ¿Por qué aquí no sirve DFS? ¿Y cómo se recuperan los movimientos si BFS solo guarda distancias?

Solución

Por qué BFS y no DFS: cada movimiento cuesta 1, o sea el grafo es no ponderado. BFS explora por capas, así que la primera vez que toca B lo hace por un camino de longitud mínima. DFS encuentra un camino, pero puede dar un rodeo enorme.

Reconstrucción del camino (la parte nueva): al visitar una celda v desde u se guardan dos cosas — padre[v] = u y movimiento[v] = 'L'/'R'/'U'/'D'. Al terminar se sube desde B siguiendo padre[] hasta A, se acumulan las letras y se invierte la cadena. Es el mismo truco de prev[] que se usó en Dijkstra (Ejercicio 7).

  • Celda (i, j) → nodo i*m + j: así padre[] y movimiento[] son arreglos planos.
  • Marcar visitado al encolar, no al desencolar: si no, una celda entra varias veces a la cola.
  • El juez acepta cualquier camino de longitud mínima; la cadena exacta depende del orden de los vecinos.

Complejidad: O(n·m). Respuesta del ejemplo: YES / 9 / LDDRRRRRU.

Java int[] di = {1, -1, 0, 0}, dj = {0, 0, 1, -1}; char[] letra = {'D', 'U', 'R', 'L'}; // misma posición que di/dj int[] padre = new int[n * m]; // ¿de qué celda vengo? char[] movimiento = new char[n * m]; // ¿con qué letra llegué? boolean[] visitado = new boolean[n * m]; Queue<Integer> cola = new ArrayDeque<>(); visitado[inicio] = true; cola.add(inicio); while (!cola.isEmpty()) { int u = cola.poll(); if (u == fin) break; // ya es óptimo: BFS por capas int i = u / m, j = u % m; for (int d = 0; d < 4; d++) { int ni = i + di[d], nj = j + dj[d]; if (ni < 0 || ni >= n || nj < 0 || nj >= m) continue; if (g[ni][nj] == '#') continue; int v = ni * m + nj; if (visitado[v]) continue; visitado[v] = true; padre[v] = u; // ← la clave de la reconstrucción movimiento[v] = letra[d]; cola.add(v); } } if (!visitado[fin]) return new String[]{"NO"}; StringBuilder camino = new StringBuilder(); for (int act = fin; act != inicio; act = padre[act]) camino.append(movimiento[act]); camino.reverse(); // se armó de B hacia A return new String[]{"YES", "" + camino.length(), camino.toString()};

Ejercicio 32 — Cyclic Components

Codeforces 977E · rating 1500 codeforces.com/problemset/problem/977/E DFS

Contar las componentes conexas que son un ciclo

Grafo no dirigido de n vértices y m aristas, sin bucles ni aristas repetidas. Una componente conexa es un ciclo si sus vértices se pueden ordenar v1—v2—…—vk—v1 y no tiene ninguna arista más (por definición, k ≥ 3). Contar cuántas componentes son ciclos.

Restricciones: 1 ≤ n ≤ 2·10⁵ , 0 ≤ m ≤ 2·10⁵ Ejemplo de entrada Salida 5 4 1 1 2 3 4 Componentes: {1,2} y {3,4,5} 5 4 {3,4,5} es el triángulo 3-4-5-3 ✔ 3 5 {1,2} es una arista suelta ✘

Pregunta: ¿hay que encontrar los ciclos con DFS y aristas de retroceso? ¿O hay una caracterización mucho más barata?

Solución

No hay que buscar el ciclo. La observación que resuelve el problema:

Una componente conexa es un ciclo simple ⟺ todos sus vértices tienen grado exactamente 2.

  • Si algún vértice tiene grado 1 → hay una "cola" colgando, no es un ciclo.
  • Si algún vértice tiene grado ≥ 3 → hay una rama o una cuerda, tampoco.
  • Si todos tienen grado 2 y la componente es conexa, entonces cada vértice tiene exactamente dos vecinos y la componente se cierra sobre sí misma: es un único ciclo.

Algoritmo: se calculan los grados al leer las aristas, se recorre cada componente con DFS (pila explícita: n llega a 2·105) y basta con que un vértice tenga grado ≠ 2 para descartarla.

Complejidad: O(n + m). Respuestas de los ejemplos: 1 y 2.

Java public static int componentesCiclo(int n, int[][] aristas) { List<List<Integer>> adj = nuevaAdj(n + 1); // vértices 1..n int[] grado = new int[n + 1]; for (int[] e : aristas) { adj.get(e[0]).add(e[1]); adj.get(e[1]).add(e[0]); grado[e[0]]++; grado[e[1]]++; // ← todo el problema vive aquí } boolean[] visitado = new boolean[n + 1]; int ciclos = 0; for (int inicio = 1; inicio <= n; inicio++) { if (visitado[inicio]) continue; boolean esCiclo = true; // DFS de la componente Deque<Integer> pila = new ArrayDeque<>(); visitado[inicio] = true; pila.push(inicio); while (!pila.isEmpty()) { int u = pila.pop(); if (grado[u] != 2) esCiclo = false; // basta UNO for (int v : adj.get(u)) { if (!visitado[v]) { visitado[v] = true; pila.push(v); } } } if (esCiclo) ciclos++; } return ciclos; }

Nota: no se puede parar el DFS apenas se ve un grado ≠ 2 — hay que terminar de marcar toda la componente para no contarla de nuevo desde otro vértice.

Ejercicio 33 — Two Buttons

Codeforces 520B · rating 1400 codeforces.com/problemset/problem/520/B BFS

Mínimo de pulsaciones para llegar de n a m

Un aparato muestra el número n. El botón rojo multiplica por 2 y el botón azul resta 1. Si el número deja de ser positivo el aparato se rompe. ¿Cuál es el mínimo número de pulsaciones para que la pantalla muestre m?

Restricciones: 1 ≤ n, m ≤ 10⁴ (n ≠ m) Ejemplo 1 Ejemplo 2 Entrada: 4 6 Entrada: 10 1 Salida: 2 Salida: 9 4 --azul--> 3 --rojo--> 6 10 -1 -1 ... -1 -> 1 (2 pulsaciones) (9 pulsaciones)

Pregunta: aquí no hay ningún grafo en el enunciado… ¿y aun así es un problema de BFS? ¿Cuál es el nodo y cuál la arista? ¿Hasta qué número hay que explorar?

Solución

Modelar el grafo — este es el aporte del ejercicio:

  • Nodo = el número que muestra la pantalla.
  • Arista = una pulsación: x → 2x (rojo) y x → x−1 (azul).
  • Toda arista cuesta 1 pulsación ⇒ grafo no ponderado ⇒ BFS da el mínimo.

Acotar el universo de estados: el grafo es infinito, así que hay que recortarlo. Pasarse de 2m nunca ayuda: desde ahí solo se puede bajar de a 1, y llegar a m desde más allá de 2m cuesta más que no haber duplicado. Con la cota 2m el grafo tiene O(m) nodos.

Complejidad: O(m) tiempo y memoria — con m ≤ 104 sobra. Respuestas: 2 y 9.

Java — BFS sobre estados public static int twoButtonsBfs(int n, int m) { int limite = Math.max(n, 2 * m); // pasarse de 2m no sirve int[] dist = new int[limite + 1]; Arrays.fill(dist, -1); Queue<Integer> cola = new ArrayDeque<>(); dist[n] = 0; cola.add(n); while (!cola.isEmpty()) { int x = cola.poll(); if (x == m) return dist[x]; // botón rojo: x → 2x if (2L * x <= limite && dist[2 * x] == -1) { dist[2 * x] = dist[x] + 1; cola.add(2 * x); } // botón azul: x → x−1 (debe seguir siendo positivo) if (x - 1 >= 1 && dist[x - 1] == -1) { dist[x - 1] = dist[x] + 1; cola.add(x - 1); } } return dist[m]; }

Bonus — la versión del editorial, O(log m): se va de m hacia n deshaciendo pulsaciones. Si m es impar la última tuvo que ser el botón azul; si es par, lo barato es deshacer la duplicación. Sirve para comparar "modelar y usar BFS" contra "pensar el problema al revés":

Java — greedy inverso public static int twoButtonsGreedy(int n, int m) { int pasos = 0; while (m > n) { if (m % 2 == 1) m++; // deshacer un "restar 1" else m /= 2; // deshacer un "multiplicar por 2" pasos++; } return pasos + (n - m); // abajo de n solo quedan restas } // Verificado: coincide con el BFS para todo 1 ≤ n, m ≤ 300

Ejercicio 34 — BFS: Shortest Reach

HackerRank · Interview Kit hackerrank.com/challenges/bfsshortreach BFS

Distancias desde un nodo, con aristas de peso 6

Grafo no dirigido donde cada arista pesa 6 unidades y los nodos están numerados de 1 a n. Dado un nodo de inicio s, devolver la distancia mínima de s a cada uno de los otros n−1 nodos, en orden de número de nodo, usando -1 para los nodos inalcanzables.

Restricciones: q ≤ 10 consultas, 2 ≤ n ≤ 1000 Ejemplo de entrada Salida Explicación 2 6 6 -1 n=4, s=1: 1-2 y 1-3 a 6; 4 2 -1 6 el nodo 4 está aislado 1 2 1 3 n=3, s=2: el 1 es 1 inalcanzable, el 3 está 3 1 a una arista (6) 2 3 2

Pregunta: el grafo es ponderado… ¿toca Dijkstra? ¿Y qué detalle del formato de salida hace fallar el envío aunque el algoritmo esté bien?

Solución

No hace falta Dijkstra. El grafo es ponderado, pero con peso uniforme: todas las aristas valen 6. Si un camino tiene k aristas, cuesta 6k, así que minimizar el costo es minimizar el número de aristas — exactamente lo que hace BFS. Se cuentan aristas y al final se multiplica por 6.

Es la misma razón por la que BFS resuelve caminos mínimos en grafos no ponderados: el argumento no necesita que el peso sea 1, solo que sea el mismo en todas las aristas. Dijkstra daría el mismo resultado pero con un O(m log n) innecesario.

  • Detalle del formato: el arreglo de salida tiene n−1 posiciones — hay que saltarse el nodo origen.
  • Los nodos van de 1 a n: se reservan n+1 casillas y se ignora la 0.
  • dist[] = -1 sirve a la vez como "no visitado" y como respuesta de inalcanzable.

Complejidad: O(n + m) por consulta. Respuestas: 6 6 -1 y -1 6.

Java public static int[] shortestReach(int n, int[][] aristas, int s) { final int PESO = 6; List<List<Integer>> adj = nuevaAdj(n + 1); // nodos 1..n for (int[] e : aristas) { adj.get(e[0]).add(e[1]); adj.get(e[1]).add(e[0]); } int[] dist = new int[n + 1]; Arrays.fill(dist, -1); // -1 = no visitado = inalcanzable Queue<Integer> cola = new ArrayDeque<>(); dist[s] = 0; cola.add(s); while (!cola.isEmpty()) { int u = cola.poll(); for (int v : adj.get(u)) { if (dist[v] == -1) { dist[v] = dist[u] + 1; // se cuentan ARISTAS, no peso cola.add(v); } } } int[] respuesta = new int[n - 1]; // ¡sin el origen! int k = 0; for (int v = 1; v <= n; v++) { if (v == s) continue; respuesta[k++] = (dist[v] == -1) ? -1 : dist[v] * PESO; } return respuesta; }

Ejercicio 35 — Roads and Libraries

HackerRank · Interview Kit hackerrank.com/challenges/torque-and-development DFS

Costo mínimo para que todos tengan biblioteca

HackerLand tiene n ciudades sin conexiones. Se puede construir una biblioteca en cualquier ciudad (costo c_lib) y carreteras bidireccionales entre los pares de ciudades de una lista dada (costo c_road cada una). Un ciudadano tiene acceso si su ciudad tiene biblioteca o puede llegar por carretera a una que la tenga. Hallar el costo mínimo total.

Restricciones: n ≤ 10⁵, m ≤ 10⁵, costos ≤ 10⁵ Consulta 1: n=3, c_lib=2, c_road=1 Consulta 2: n=6, c_lib=2, c_road=5 carreteras: 1-2, 3-1, 2-3 carreteras: 1-3, 3-4, 2-4, Salida: 4 1-2, 2-3, 5-6 Salida: 12

Pregunta: ¿hace falta un MST (Kruskal/Prim) para elegir las carreteras? ¿Y qué pasa con el tipo de dato de la respuesta?

Solución

Nada de MST. Todas las carreteras cuestan lo mismo, así que no hay que elegir cuáles: solo importa cuántas. Conectar una componente de k ciudades cuesta siempre k−1 carreteras (cualquier árbol de expansión sirve), y Kruskal solo aportaría un sort inútil.

Dos casos:

  • Si c_lib ≤ c_road: nunca conviene una carretera → una biblioteca por ciudad: n · c_lib.
  • Si c_lib > c_road: conviene conectar. En cada componente conexa basta 1 biblioteca y k−1 carreteras. Con C componentes y n ciudades en total:
    costo = C · c_lib + (n − C) · c_road

Las C componentes se cuentan con el mismo DFS del Ejercicio 2 / 30. El grafo solo se usa para contar componentes — la decisión es aritmética.

Desbordamiento: 105 ciudades × 105 de costo = 1010, que no cabe en un int. Hay que usar long: es el error más frecuente en este problema.

Verificación: consulta 1 → c_lib(2) > c_road(1), 1 componente: 1·2 + (3−1)·1 = 4. Consulta 2 → c_lib(2) ≤ c_road(5): 6·2 = 12.

Complejidad: O(n + m).

Java public static long roadsAndLibraries(int n, long cLib, long cRoad, int[][] ciudades) { // Caso 1: la biblioteca no cuesta más que la carretera if (cLib <= cRoad) return (long) n * cLib; // ← el cast importa // Caso 2: conviene conectar → contar componentes con DFS List<List<Integer>> adj = nuevaAdj(n + 1); for (int[] c : ciudades) { adj.get(c[0]).add(c[1]); adj.get(c[1]).add(c[0]); } boolean[] visitado = new boolean[n + 1]; long componentes = 0; for (int inicio = 1; inicio <= n; inicio++) { if (visitado[inicio]) continue; componentes++; Deque<Integer> pila = new ArrayDeque<>(); visitado[inicio] = true; pila.push(inicio); while (!pila.isEmpty()) { int u = pila.pop(); for (int v : adj.get(u)) { if (!visitado[v]) { visitado[v] = true; pila.push(v); } } } } // 1 biblioteca por componente + (n − C) carreteras return componentes * cLib + (n - componentes) * cRoad; }
